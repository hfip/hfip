## Profile

I build small, focused tools and ship Arabic translations for open-source software. Most of my work sits where native apps meet the command line: SwiftUI interfaces, automation scripts, and the localization layer that makes an app read naturally in Arabic rather than merely translated.

## What I work on

- **Apple platforms** — Swift and SwiftUI apps and utilities, from the interface down to build tooling.
- **Localization** — complete Arabic passes: string catalogs, RTL layout, Arabic plural rules, and terminology that stays consistent across every screen.
- **Automation** — Python, Node and shell tooling for repetitive workflows, data handling and self-hosted services.
- **Media tooling** — bridges and add-ons around self-hosted media servers.

## Tooling

I keep a small set of Arabic and RTL tools for Apple development — layout linting, String
Catalog coverage, Arabic plural rules, bidi inspection, subtitle repair. Each one is a
separate repository with its own tests.

[Arabic dev tools →](https://github.com/hfip/arabic-dev-tools)

## Selected work

- Complete Arabic localizations for open-source Apple apps — string catalogs, RTL passes,
  plural forms and terminology.
- Upstream contributions to iOS tools and utilities, merged with credit.
- Arabic-first media tooling and self-hosted bridges.

## How I work

- Read the code before the strings: keys, placeholders and context first.
- Keep changes small and reviewable — one concern per pull request.
- Verify with the project's own tests, and state plainly what was not verified.
- Leave documentation behind, so the next contributor does not have to reverse-engineer the change.
